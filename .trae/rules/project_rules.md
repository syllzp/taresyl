# 前后端分离项目规则

## 1. 项目结构

### 1.1 目录结构
- **后端**：位于 `backend/` 目录，使用 Django 5.2 + Django REST Framework 构建
- **前端**：位于 `frontend/` 目录，使用 Vue 3 + Element Plus 构建
- **代码仓库**：保持单一代码仓库，便于版本管理和部署

### 1.2 后端结构
- 采用 Django 模块化应用结构
- 每个功能模块作为独立的 Django app
- 核心配置位于 `backend/core/` 目录
- API 路由统一管理，遵循 RESTful 设计原则

### 1.3 前端结构
- 采用 Vue 3 Composition API
- 组件化开发，遵循单一职责原则
- 路由配置清晰，支持嵌套路由
- 状态管理合理使用（如需）

## 2. 通信规则

### 2.1 API 设计
- **RESTful 风格**：使用标准 HTTP 方法（GET, POST, PUT, DELETE）
- **URL 规范**：后端 API 前缀统一为 `/api/`
- **数据格式**：所有 API 返回 JSON 格式数据
- **状态码**：使用标准 HTTP 状态码表示请求结果
- **错误处理**：统一的错误响应格式，包含错误码和错误信息

### 2.2 前端请求
- 使用 Axios 进行 HTTP 请求
- 统一的 API 服务层，封装请求逻辑
- 合理的错误处理和加载状态管理
- 支持请求超时和重试机制

### 2.3 跨域处理
- 后端配置 CORS，允许前端域名访问
- 开发环境使用本地服务器，生产环境配置真实域名
- 避免使用 `*` 通配符，明确指定允许的域名

## 3. 数据管理

### 3.1 数据流转
- **前端**：负责数据展示、用户交互和表单验证
- **后端**：负责业务逻辑、数据存储和安全验证
- **数据流**：前端 → API 请求 → 后端处理 → 数据库操作 → 后端响应 → 前端更新

### 3.2 数据验证
- **前端验证**：即时反馈，提升用户体验
- **后端验证**：确保数据安全性和一致性
- **双重验证**：关键操作必须在前后端都进行验证

### 3.3 状态管理
- **前端状态**：使用 Vue 3 的响应式系统或 Pinia
- **后端状态**：通过数据库和缓存管理
- **会话管理**：使用 JWT 进行无状态认证

## 4. 开发规范

### 4.1 代码风格
- **后端**：遵循 PEP 8 代码规范
- **前端**：遵循 Vue 官方风格指南
- **命名规范**：统一使用英文命名，避免中文和拼音
- **注释规范**：关键逻辑和复杂代码必须添加注释

### 4.2 版本控制
- 使用 Git 进行版本管理
- 合理的分支策略（如 main, develop, feature 分支）
- 提交信息清晰，遵循约定式提交规范
- 定期合并和代码审查

### 4.3 依赖管理
- **后端**：使用 `requirements.txt` 管理 Python 依赖
- **前端**：使用 `package.json` 管理 Node.js 依赖
- 固定依赖版本，避免版本冲突
- 定期更新依赖，确保安全性

## 5. 安全规范

### 5.1 API 安全
- **认证**：使用 JWT 进行身份验证
- **授权**：基于角色的权限控制
- **速率限制**：防止 API 滥用
- **输入验证**：严格验证所有用户输入

### 5.2 数据安全
- **密码存储**：使用 Django 的密码哈希机制
- **敏感数据**：加密存储敏感信息
- **传输安全**：生产环境使用 HTTPS
- **CORS 配置**：合理配置跨域资源共享

### 5.3 前端安全
- **XSS 防护**：使用 Vue 的内置 XSS 防护
- **CSRF 防护**：遵循 Django 的 CSRF 保护机制
- **敏感信息**：不在前端存储敏感信息
- **API 密钥**：避免在前端代码中硬编码 API 密钥

## 6. 部署规范

### 6.1 开发环境
- **后端**：使用 Django 开发服务器 (`python manage.py runserver`)
- **前端**：使用 Vite 开发服务器 (`npm run dev`)
- **数据库**：使用 SQLite 进行开发
- **配置**：使用环境变量或配置文件管理不同环境的配置

### 6.2 生产环境
- **后端**：使用 Gunicorn 或 uWSGI 作为 WSGI 服务器
- **前端**：构建静态文件，使用 Nginx 或 CDN 部署
- **数据库**：使用 PostgreSQL 或 MySQL 等生产级数据库
- **监控**：配置日志和监控系统

### 6.3 容器化（可选）
- 使用 Docker 容器化部署
- 提供 Dockerfile 和 docker-compose.yml
- 确保容器间网络通信安全

## 7. 测试规范

### 7.1 后端测试
- 使用 Django 的测试框架
- 编写单元测试和集成测试
- 测试覆盖率目标：≥ 80%
- 定期运行测试套件

### 7.2 前端测试
- 使用 Vue Test Utils 和 Jest
- 编写组件测试和端到端测试
- 测试用户交互和边界情况
- 确保关键功能的测试覆盖

### 7.3 集成测试
- 测试前后端集成场景
- 模拟真实用户操作流程
- 验证 API 响应和前端处理

### 8.1 API 文档

- 包含请求示例和响应格式

### 8.2 项目文档

## 9. 工作流规范

### 9.1 开发流程
- **需求分析**：明确功能需求和技术要求
- **任务拆分**：将需求拆分为可管理的任务
- **代码开发**：遵循编码规范，编写高质量代码
- **代码审查**：提交前进行自我审查，团队成员交叉审查
- **测试验证**：运行测试套件，确保功能正常
- **部署上线**：按照部署流程发布代码

### 9.2 协作规则
- **分支管理**：功能开发使用 feature 分支，bug 修复使用 hotfix 分支
- **代码提交**：小而频繁的提交，避免大爆炸式提交
- **冲突解决**：及时同步主分支，减少合并冲突
- **问题追踪**：使用项目管理工具跟踪任务和问题

### 9.3 性能优化
- **前端优化**：组件懒加载、资源压缩、缓存策略
- **后端优化**：数据库索引、查询优化、缓存使用
- **API 优化**：合理的分页、字段选择、请求合并
- **部署优化**：负载均衡、水平扩展、CDN 使用
